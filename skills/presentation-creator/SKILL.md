# Presentation Creator

Turn a brief, outline, or source document into a polished `.pptx` deck, then run a
deterministic QA pass before delivering it. The deck is generated by
`scripts/build_deck.py` from a JSON spec, so output is reproducible and reviewable; custom
layouts get hand-written python-pptx code using `references/python-pptx-recipes.md`.

## When to use

Activate when the user asks for slides, a deck, a presentation, a pitch, a keynote, a slide
outline, or wants to turn a document/README/notes into slides. Also activate when an existing
`.pptx` needs a rebuild, restyle, or QA pass.

## Workflow

### 0. Preflight

Confirm the toolchain before promising output:

```sh
python3 -c "import pptx; print(pptx.__version__)"
```

- If it fails, create a venv (`python3 -m venv /tmp/pptx-venv && /tmp/pptx-venv/bin/pip install python-pptx`)
  or `pip install --user python-pptx`. Ask before installing into system site-packages.
- `matplotlib`/`Pillow` are only needed for chart/image slides; `soffice` (LibreOffice) only
  for the optional PDF preview. Missing optional pieces downgrade the feature, not the task.
- `references/troubleshooting.md` covers missing-font and preview gaps.

### 1. Clarify (max 3 questions)

Ask only what changes the output; infer the rest and state assumptions. Cover:

- **Audience** and **goal** (inform, persuade, teach, pitch).
- **Length**: slide count or talk duration (≈1 slide / minute as a default).
- **Tone/brand**: preset theme, brand colors, fonts, logo.
- **Output path** and aspect (default 16:9).

If the user gives a source document, derive audience/goal from it and confirm briefly.

### 2. Outline

Draft the deck as assertion-style headlines (a full sentence that states the takeaway, not a
label like "Overview"). Budget slides, cap bullets at ≤5 per slide, and write one paragraph of
speaker notes per slide. Show the outline to the user when the deck is non-trivial or the
brief is ambiguous; otherwise proceed.

### 3. Theme

Pick one preset from `references/design-system.md` (`clean-light`, `corporate-blue`,
`dark-tech`) unless brand colors are supplied. Canvas is 16:9 (13.333in × 7.5in). Keep the
type scale, palette, and grid from the preset so slides stay consistent.

### 4. Build

Author a JSON deck spec (see `examples/example-deck.json` and the contract below) and run:

```sh
python3 scripts/build_deck.py deck.json -o deck.pptx
```

`--force` is required to overwrite an existing file. For slides the spec can't express, write
python-pptx code directly using `references/python-pptx-recipes.md`, then keep the deck on the
same theme objects so it stays visually consistent.

### 5. QA gate

```sh
python3 scripts/validate_deck.py deck.pptx
```

Fix every reported error and re-run until it exits 0 (warnings-only also exits 0). The
validator checks slide-bounds, estimated text overflow, font floors, bullet counts, missing
titles/notes, duplicate titles, and WCAG contrast. Do not deliver a deck that fails the gate.

### 6. Optional preview

If LibreOffice is available:

```sh
soffice --headless --convert-to pdf --outdir <dir> deck.pptx
```

If it is absent, say so explicitly and skip; do not claim a preview was rendered.

### 7. Deliver

Report the output path, slide count, theme, assumptions made, and any checks that were
skipped. Confirm before overwriting an existing file, and never download remote images
without approval.

## JSON deck spec contract

Top-level keys:

| Key | Required | Notes |
|---|---|---|
| `title` | yes | Deck title (used on the title slide). |
| `subtitle` | no | Subtitle / tagline. |
| `theme` | no | `clean-light` (default), `corporate-blue`, `dark-tech`. |
| `aspect` | no | `16:9` (default) or `4:3`. |
| `slides` | yes | List of slide objects. |

Each slide: `layout` ∈ `title, section, bullets, two_column, image, table, quote, chart,
closing`, plus `notes`. Common fields: `title`, `subtitle`, `bullets` (strings), `columns`
(two lists for `two_column`), `table` (`headers` + `rows`), `image` (`path`), `quote`
(`text` + `attribution`), `chart` (`type` ∈ `bar, line, pie`, `categories`, `series`
`[{name, values}]`).

## Safety and constraints

- Deterministic output: prefer the builder over ad-hoc script edits.
- No network: never fetch remote images or fonts without explicit approval.
- Keep the QA gate as a hard requirement; overflow and low contrast are delivery blockers.
